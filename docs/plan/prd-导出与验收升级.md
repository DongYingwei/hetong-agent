## 1. 问题定义

用户用自然语言向合同库提问,系统自主选路——结构化统计、语义原文检索、或二者联动——返回**可核验、不幻觉、路由与出处数值均正确**的答案,并支持把结构化结果导出为 Excel。

本次是在已端到端建成系统(T01–T08、T10 完成,上传核对闭环打通)上的**增量**,不是从零设计。新增能力聚焦一处:**结构化结果导出**。

---

## 2. 目标用户

经小管合同管理的**业务与运营人员**(经管专家视角)。用大白话问合同,不需要理解 SQL、表结构或向量检索。既有透明度设计(SQL 折叠框 + 出处三要素)让他们能自行核验每个数字的来源。

---

## 3. 核心场景

| 场景 | 路径 | 说明 |
|---|---|---|
| **服务内容含 AI 智能体的合同有几份、编号、总金额** | R1/R5 · 模块命中 → SQL 统计 → 汇总表 → **导出 .xlsx** | 占比最大,是本次新增导出的主场景 |
| **针对合同 xx,违规了合同上说怎么处理** | R4+R2 · 单合同锁定 → 片段内检索 → 带出处原文答案 | 已有能力,无需新建 |

另含 R3 语义路由到统计、R5 模块化细粒度查询——均为既有能力。复杂提问占比小,**不限制提问方式**,由 Agent 尽力自主编排。

---

## 4. 范围

### 范围内
- **前端 Excel 导出** — 用已装的 `exceljs` 把 `tableData` 落 .xlsx,**忠实导出、不二次聚合**。
- **保留提示词级多步规划** — 既有的自主选路 / 向量→SQL 串行联动 / 单合同追问 / 自纠错(≤2 次),不阉割。
- **验收口径升级** — 在轨迹正确之上,要求路由对 + 出处对 + 数值可核验(前提:数据已人工核对)。

### 范围外
- **抽取质量修复** — 金额/日期空、模块命中 0(handoff 遗留 B),后续另排。
- **引擎级规划状态机** — `loop.planning` / CoreMind 0.3.x 升级,暂缓(见 §8)。
- **网关/Agent 侧导出工具** — 导出留在前端,不新增工具或路由。
- **数值真值自动 gate** — 需 G4 人工标注集;阈值/top_k 调参基线;多轮 turns eval。

---

## 5. 业务规则

| 规则 | 说明 |
|---|---|
| **导出忠实** | Excel 逐行等于屏幕表,导出层不做任何二次聚合;尤其**不得跨 `amount_type` 合计**——"总金额"须由 Agent 在 SQL 侧按口径给出,导出照搬。 |
| **D4 金额口径** | `SUM(amount)` 一律带 `amount IS NOT NULL`;上限/固定/预估分组不合一;税率是文本,不做算术。 |
| **D1–D7 纪律** | 只读三防线、串行不并发、不幻觉、出处透明——全部保留,导出不引入例外。 |
| **已背书数据** | 仅核对入正式库(`confirmed=1`)才建向量并可查;草稿区永不查。 |

---

## 6. 异常与边界场景

- **空结果 / 低相似度** — 如实说"未检索到满足条件的记录 / 未找到足够相关原文",不放宽条件、不编造(D2)。
- **混口径结果集导出** — Excel 按 Agent 已分行的口径落,**不加"总计"行**(否则违 D4)。
- **无金额合同**(框架协议,`amount IS NULL`) — 作为合法类别计数,不进金额求和。
- **SQL 报错** — 自纠错重试 ≤2 次,仍失败则如实报告,不猜答案。
- **提问超出单回合串行能力** — 尽力而为,不静默给错;这是引擎级 Planner 的未来触发条件。

---

## 7. 验收标准

本次采用**数值可核验**口径(非数值真值自动比对),前提是入库数据已人工核对。

| 编号 | 标准 | 度量 |
|---|---|---|
| **V-路由** | 路由正确 | 纯统计不触发向量;语义走精排;联动串行不并发。 |
| **V-出处** | 出处完整 | RAG 答案带合同号+字段+原文引用;SQL 结果可展开"查看 SQL"。 |
| **V-数值** | 数值可核验 | 不做真值自动比对,但每个数字都能经 SQL/出处人工回溯,抽检 0 编造。 |
| **V-导出** | 导出忠实 | .xlsx 与屏幕表逐行一致,无新增聚合、无口径合并。 |

## 8. 已确认决策

grilling 逐题拍板,不可逆边界已落 ADR-0005 并同步 CONTEXT.md 术语。

| 问题 | 决策 | 主要取舍 |
|---|---|---|
| **Q1** | 扩展既有系统 | 链路已建成,做增量而非重设计。 |
| **Q2** | 现有两工具够用,新增仅"导出" | 真实例子均单路径/两步串行,无需 Planner。 |
| **Q3** | 抽取质量出范围 | 最薄弱环节,但本次不碰,后续另议。 |
| **Q5** | 前端导出 | `apps/web` 已装 exceljs,纯展示层动作,不进 Agent。 |
| **Q6** | 忠实导出,不再合计 | 底部加总计会把混口径合一,违 D4。 |
| **Q7** | 数值可核验(非真值 gate) | 真值比对阻塞在 G4 标注集,先可核验达标。 |
| **Q8** | 提示词级 ReAct,不升 CoreMind | 引擎级 Planner 是不可逆升级,撞坑7/坑10,无真实需求。 |

**CoreMind 维持 0.2.0-rc.1。** 升级到 0.3.0-rc.2 经评估暂缓——它只换执行内核(成本闸/上下文压缩/安全修复),**不带来任何检索/RAG 能力**,零新能力进入本次范围,却付出不可逆改动 + 重跑 28 vitest / 40 pytest 的确定成本。触发升级的条件:真出现"多合同对比 / 跨子问题聚合"等单回合串行做不到的提问 —— 届时一次升级 + 推翻 ADR-0005 + 解决坑7/坑10 共存。
