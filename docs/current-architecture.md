# 当前架构与维护边界

最后更新：2026-08-20。本文是当前实现的事实说明；历史设计与旧分期计划不作为运行依据。

## 1. 数据域与写入边界

| 数据域 | 数据库/存储 | 写入方 | 读取方 | 真相来源 |
|---|---|---|---|---|
| 合同台账、附件、草稿、核对、切片 | PostgreSQL `contracts`、`/data/jingxiaoguan/contracts` | Parse Service | Gateway、Query Agent | 审核版合同台账 + 人工核对 |
| 合同正文向量 | Milvus | Parse Service | Query Agent | 已确认合同的前 50 页 Markdown |
| 订单、权限、关键词、会话、日志 | PostgreSQL `contract_assistant` | Gateway、EPMS 导入 | Gateway、Query Agent | 审核时间全量订单 Excel + 人工编辑 |
| 订单附件与解析文本 | `/data/jingxiaoguan/epms/{EPMS,md-epms}` | EPMS Sync | 模块分析脚本 | EPMS 上游附件 |

`contracts` 与 `contract_assistant` 是不同数据库，禁止跨库混用连接串或表名。

## 2. 合同生命周期

```text
单文件 / 多附件 / ZIP 合同包
  → 保存原件（多 PDF 均保留）
  → 解析 Markdown（最多前 50 页）
  → Qwen 字段抽取，必要时 DeepSeek 兜底
  → 草稿与四模块关键词命中
  → 人工填写真实合同号、核对和编辑
  → contracts 正式记录 + contract_manual_reviews
  → 切片、Embedding、Milvus
```

- 同一合同可以有多份不同 PDF；内容 SHA-256 完全一致的重复附件只保留一份来源记录。
- 草稿临时编号为内部 `DRAFT-*`，在人工核对页不展示；确认时必须填写真实合同号，且长度不超过 Milvus metadata 限制。
- 只允许 `confirmed=1` 的合同入向量库。新上传、重解析合同均应保持待核对，不能因历史批量核对状态自动视为已核对。

## 3. AI 关键词与四模块

关键词管理有父词（所属大类）和子词（实际命中词）。全文扫描先生成 `tag_ai`，再按段落/标题位置落入四个固定模块：

1. 项目名称
2. 服务内容
3. 技术要求
4. 人员需求

模块命中任一启用子词即显示 `AI`，否则显示 `—`。不做同义词扩展，不能将英文单词片段误拆为 `AI`。关键词重扫只改变命中明细、模块标记和 `tag_ai`；不重新解析、切片或建向量。

合同和订单的人工关键词调整必须从当前启用的关键词下拉选择。订单编辑直接写 `sys_order`，并同步其模块命中与 `tag_ai`；之后查询、统计、导出以编辑后的订单主表为准。

## 4. 台账与前端

- 合同台账已核对记录主操作为“查看”，待核对记录主操作为“核对”；查看只读，更多菜单的编辑才可修改。
- 合同详情必须保留六页签，并在原文件预览中列出全部 PDF。
- 订单详情与编辑分开：详情只读，编辑允许修改订单字段和关键词解析结果。
- 合同/订单筛选支持关键词管理下的 AI、通信等启用关键词；四模块筛选固定为上述四项，模块配置变更后更新筛选配置。
- 关键词管理主表不展示大面积“包含子词”列，展开行查看子词；UI 使用统一主题色。
- 订单台账 Excel 导出遍历当前筛选条件下全部分页数据，不使用当前页面数据；导出保留原始字段、AI 是否命中与命中词，禁止填充演示默认值。

## 5. 综合检索边界

Gateway 的 Harness 将请求分为：合同 SQL、订单 SQL、合同原文 RAG、受控混合业绩、澄清/拒答。

- 结构化查询必须返回对应台账明细（合同 15 列、订单 17 列），默认前 5 条且可展开全部；导出保留 Excel 完整表头与数据。
- RAG 仅检索合同正文向量；回答应给出合同号、字段和原文依据，不展示 SQL、提示词或内部工具轨迹。
- 合同和订单默认不混算。混合业绩仅可基于已确认的合同—订单关联；关联数据尚未提供，正式业务统计暂不启用。
- 无关问候/天气/翻译等给出能力引导；超过 8,000 字的输入提示拆分。运行时最多 6 轮、12 步、3 次工具调用，总超时 120 秒。

### 当前需继续验证/修复的检索项

1. 结构化 SQL 和 RAG 必须同时过滤页面核对状态，避免新上传但尚未核对的正式合同被返回。
2. 混合业绩的关键词过滤需使用合同关键词命中表，不能引用不存在的合同 JSON 字段。
3. 框架合同类型要统一处理 `框架` 与 `框架协议`；当前人工关联数据为零时不得输出混合金额结论。
4. Reranker 集成测试的首位排序断言不稳定，应改为“相关合同进入 Top-N”的断言后再作为发布门槛。

## 6. 模型与解析限制

- 默认字段抽取模型：`Qwen3.8-27B`（`192.168.121.32:6013`）。
- Qwen 超时、返回结构化失败，或六项关键字段不足两项时，使用 DeepSeek 兜底。
- 内容风控拒绝、超长 PDF、MinerU 或模型异常均应记录操作日志并留在草稿/失败状态；不能伪造成功。
- 每份合同固定最多识别 50 页；第 51 页以后仍可原文件预览和下载，但暂不参与关键词、向量与 RAG。
