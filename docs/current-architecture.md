# 当前架构与维护边界

## 数据边界

解析服务写合同草稿、正式合同、模块/关键词命中与向量；网关写运营库中的用户、权限、订单、关键词和重扫任务；查询智能体只读合同库、订单库和 Milvus；前端仅经网关访问。

合同库为 `contracts`，运营库为 `contract_assistant`，不得混用。合同台账的人工审核 Excel 是金额和商务字段的主基线；合同 Markdown 和 Milvus 仅用于原文检索与证据追溯。

## 合同生命周期

`PDF/附件 → Markdown → 字段抽取与模块切分 → 人工核对 → 正式合同 + 命中明细 → 向量片段`。

一个合同可对应多个 PDF。附件源文件清单、Markdown manifest、合同记录和向量 metadata 都使用 `contract_id`/包记录关联；合同详情预览应可切换全部 PDF。

重扫关键词只更新关键词命中、模块 AI 标记和 `tag_ai`，不重新解析、切片或建向量。

## 配置驱动

模块由 `contract_modules` 配置，适用范围为合同、订单或两者。列表列和筛选项必须由配置生成，禁止写死四模块。父关键词是所属大类，子词是实际命中关键词。

全文关键词扫描先给出 `tag_ai`；仅全文命中的数据再按服务内容、技术要求、项目名称、人员需求分段判定。模块命中显示 `AI`，未命中显示 `—`，不展示分段原文。

合同、订单的人工关键词调整只能从关键词管理的启用父关键词选择，不能自由输入。订单人工编辑直接写入 `sys_order`，并同步更新 `order_module_hits` 与 `tag_ai`；综合检索、统计和导出读取这些最新值。

## 权限与暂停项

权限以运营库菜单/角色权限为准；合同管理员和系统管理员可重扫关键词。合同—订单关联在提供人工确认数据前不展示入口、不参与金额混合统计。

综合检索经 Harness 分流为合同/订单结构化 SQL、合同正文 RAG 和受控混合业绩统计；工具均为只读。会话记忆由运营库持久化，面向用户只展示业务化检索过程和台账结果，不展示 SQL 或提示词。

对用户明确表达的低歧义条件（例如“考核线是运营商”“服务内容含 AI”），Gateway 会先提取约束、提示模型写入 SQL，并在补全台账后再次校验/汇总。业务别名只收录低歧义表达；单独的“通信”等正文词不自动映射为考核线。
