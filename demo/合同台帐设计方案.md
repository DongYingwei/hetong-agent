# 经小管智能体 (Contract Intelligence Agent) 设计与开发文档

## 一、 项目背景与目标
### 1.1 背景
企业合同管理长期面临三个痛点：
*   **录入难**：合同文件（PDF/扫描件）数量大，人工提取金额、条款、日期效率低。
*   **统计难**：非结构化数据难以进行“总金额”、“合同数”等量化统计。
*   **检索难**：传统关键词检索无法处理语义问题（如“是否有AI相关的服务内容”）。

### 1.2 目标
构建一个集 **自动解析、结构化提取、智能校验、混合检索** 为一体的智能体系统，实现：
1.  **自动化台账**：AI 自动填充合同概要、金额、商务条款。
2.  **高质量核对**：提供人机协作界面，确保数据 100% 准确。
3.  **智能体问答**：支持自然语言进行统计查询和条款溯源。

---

## 二、 总体技术架构
项目采用 **“双路存储 + 智能路由”** 架构：

*   **解析层**：MinerU（负责将 PDF/扫描件 转化为高保真 Markdown）。
*   **编排层**：LlamaIndex（负责数据分段、结构化提取、RAG 流程管理）。
*   **存储层**：
    *   **SQL 数据库**：存储合同概要、金额等结构化数据。
    *   **向量数据库**：存储合同文本分段及 Embedding，用于语义检索。
*   **模型层**：大语言模型（GPT-4o 或 DeepSeek-V3） + Reranker 重排序模型。
*   **展示层**：基于原型的响应式 Web 前端。

---

## 三、 核心业务流程

### 3.1 数据处理流水线 (Ingestion Pipeline)
1.  **文件解析**：MinerU 读取 PDF，输出 Markdown（含表格）。
2.  **逻辑切分**：LlamaIndex 识别 Markdown 标题，按“条款/章节”进行 Node 切分。
3.  **结构化提取**：
    *   定义 Pydantic Schema。
    *   LLM 阅读 Markdown，提取 JSON。
4.  **质量门 (Quality Gate)**：
    *   **逻辑校验**：总金额 = 分项金额之和？日期格式合法？
    *   **正则校验**：排除关键词异常上下文。
5.  **持久化**：
    *   JSON 数据存入 PostgreSQL。
    *   文本 Nodes 存入向量数据库（如 Milvus/Chroma）。

### 3.2 智能检索流程 (Query Pipeline)
1.  **提问理解**：智能体通过 LLM 判断提问类型。
2.  **路由分发**：
    *   **统计类**（如：总金额是多少？）：转换为 **Text-to-SQL**，查询数据库。
    *   **知识类**（如：某条款怎么定？）：转换为 **混合检索**（向量+关键词）。
3.  **重排序 (Reranking)**：对初筛结果进行语义精排，取前 3-5 条。
4.  **生成响应**：LLM 结合参考内容，生成“答案 + 原文引用 + 页码”。

## 四、 开发路线图

### 第一阶段：基础解析环境 (1-2周)
*   [ ] 部署 **MinerU** 服务，确保扫描件 OCR 准确率。
*   [ ] 配置 **LlamaIndex** 环境，对接 LLM API。
*   [ ] 实现 PDF 批量转化为清洗后的 Markdown。

### 第二阶段：结构化提取引擎 (2-3周)
*   [ ] 编写 **Pydantic 模型**，定义 20+ 核心合同字段。
*   [ ] 优化 **Extraction Prompt**，针对不同合同类型设置 Router。
*   [ ] 开发 **质量门模块**：实现金额计算校验、关键词二次过滤。

### 第三阶段：混合 RAG 与智能体 (3-4周)
*   [ ] 搭建向量库，实现基于 **MinerU 层级标题** 的切分策略。
*   [ ] 集成 **BM25 + Vector** 的混合搜索，引入 **BGE-Reranker**。
*   [ ] 实现 **Chat Memory**，支持针对单份或多份合同的连续追问。

### 第四阶段：UI 集成与联调 (2周)
*   [ ] 开发“人工核对”界面，支持修改 AI 提取结果并回传数据库。
*   [ ] 开发“智能对话”窗口，集成流式输出与原文溯源跳转。

## 五、 核心代码示例

### 5.1 结构化提取示例
```python
from pydantic import BaseModel, validator
from llama_index.core.program import LLMTextCompletionProgram

# 定义质量门验证逻辑
class ContractLedger(BaseModel):
    customer_name: str
    total_amount: float
    sign_date: str
    
    @validator("total_amount")
    def amount_must_be_positive(cls, v):
        if v <= 0: raise ValueError("金额异常")
        return v

# 调用 LlamaIndex 提取
program = LLMTextCompletionProgram.from_defaults(
    output_cls=ContractLedger,
    prompt_template_str="请从以下合同Markdown中提取信息：{markdown_text}"
)
```

### 5.2 智能体路由逻辑
```python
from llama_index.core.agent import ReActAgent
from llama_index.core.tools import QueryEngineTool

# 封装 SQL 和 Vector 为工具
sql_tool = QueryEngineTool.from_defaults(query_engine=sql_engine, description="负责统计金额、数量等数据")
vector_tool = QueryEngineTool.from_defaults(query_engine=vector_engine, description="负责查找合同条款描述、法律细节")

# 创建 Agent
agent = ReActAgent.from_tools([sql_tool, vector_tool], llm=llm, verbose=True)
```

## 六、 关键风险点与规避

| 风险点 | 表现 | 规避方案 |
| :--- | :--- | :--- |
| **OCR 错误** | 扫描件模糊导致数字识别错误（如 0/8 不分） | 增加逻辑校验门；在 UI 界面对置信度低的字段进行变色提醒。 |
| **幻觉问题** | AI 回答了合同中不存在的优惠政策 | 强制要求 **Source Citation**（引用溯源）；设置 `temperature=0`。 |
| **长文本截断** | 合同超过 100 页，LLM 一次看不完 | 采用 **MinerU 逻辑切分**；使用向量检索定位片段而非全量输入。 |
| **隐私合规** | 核心合同数据泄露 | 私有化部署 LLM（如本地 DeepSeek）；数据存储过程加密。 |
| **实体歧义** | 同一客户名字写法不统一 | 引入 **实体消歧 (Entity Resolution)** 模块，对接标准主数据。 |
