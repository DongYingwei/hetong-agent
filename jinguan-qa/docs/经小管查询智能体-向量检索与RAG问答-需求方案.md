# 经小管查询智能体 · 向量检索与 RAG 问答 · 需求方案

> 版本：v1.0（草案） · 生成日期：2026-08-11
> 归属：经小管合同管理智能体 · 本方案是 [经小管查询智能体模块 · 需求方案](./经小管查询智能体模块%20·%20需求方案.md) 的语义检索扩展。

## 1. 背景与目标变更

原查询模块首版定位是**结构化统计（Text-to-SQL）**，向量库明确"首版不做"。本方案将该决策**升级为"要"**：查询智能体需要处理**开放式语义提问**，典型如：

- 询问某份合同的具体细节（"这份合同的结算条款怎么约定的？"）
- 对某一合同内容的多轮追问（"那它的仲裁方式呢？"）
- 跨库语义检索（"有哪些合同的岗位要求和智能巡检类似？"）

**一句话职责扩展**：自然语言提问 →（Agent 自主判断走 SQL 统计 / 语义原文检索 / 二者联动）→ 带出处的 Markdown 答案。

## 3. 检索形态（Agent 自主编排）

用户随意提问，**由 Agent 判断**走哪条路径，不预设固定分类。三条路径共存：

| 路径 | 触发（Agent 判断） | 工具链 | 输出 |
|---|---|---|---|
| **纯统计** | 过滤维度都能命中结构化列 | `sql_query` | Markdown 表格 + 数值 |
| **RAG 原文问答** | 问的是合同**内容/细节/条款语义** | `vector_search`（召回+精排）→ 生成 | 自然语言/表格答案 + **原文出处** |
| **语义路由到统计** | "类似/相关"类模糊词需落到计数/求和 | `vector_search`（返回 ids）→ `sql_query` | 表格 + 数值 |

- **自主编排**：靠 CoreMind 的 **Harness（工具层）+ 记忆层（session）+ skills（数据字典）**，由 systemPrompt 引导 Agent 选路径，无独立 Planner 组件。
- **单合同锁定**：用户定位到某合同后，追问只在该合同片段内检索。首版靠 **session 历史 + prompt** 让 Agent 推断当前 `contract_id` 并带入 `filters`，不引入显式状态工具（留二版增强）。

## 4. 两阶段检索架构（核心）

基于本地现成设施：**Milvus + qwen3-embedding-4B + qwen3-reranker-4B**。

```
① 召回 (Recall)：qwen3-embedding-4B 对提问生成向量
                 → Milvus 向量相似度检索 + 标量过滤（metadata）
                 → top_k = 50（较大，追求不漏）
② 精排 (Rerank)：qwen3-reranker-4B 对 50 个片段与提问做交叉打分
                 → 重排取 top_n = 8（较小，最相关在前）
③ 消费：top_n 片段 → RAG 生成（带出处）
        或 片段的 contract_ids → 回 PG 做 SQL 二次统计
```

- **混合检索**：Milvus 标量字段存 `contract_id / contract_no / field / module_category`，支持"先标量过滤（锁定某合同 / 某字段）再向量召回"。
- **联动衔接**：Milvus 与 PG 不同库，靠 `contract_id` 回 PG JOIN/统计（复用现有 `vector_search` 只返回 id 的契约）。
- **端点封装**：embedding / reranker / Milvus 的连接细节封在工具内、从 env 读；对 CoreMind 只暴露 read 语义（契合 `permissions.network: deny`）。

## 5. 向量化数据（范围与切分）

### 5.1 范围：合同全文

- 向量化**合同全文分段片段**，而非仅 7 类长文本字段。
- **依据**：MinerU 解析后即可获取整份合同带格式的完整分段片段——在解析阶段现成、无需重解析。
- 覆盖前言/定义/通用条款/签署页等此前不进 7 类字段的原文，任何一句都可被追问命中。

### 5.2 切分：结构感知

- 先按结构（章节/字段来源）切"父块"，超长再按条款/段落二次切；**重叠 1–2 句**防条款被切断。
- **四模块（服务内容/技术要求/岗位说明/人员需求）单独存储**——支撑细粒度检索与按模块粒度增量更新。
- 每片 metadata：`{contract_id, contract_no, field（来源字段/章节）, module_category（AI 大方向）}`。

### 5.3 归属

- **片段产出 + 建向量在解析侧**：解析模块在 ETL 时持久化 MinerU 完整分段片段并写入 Milvus。
- 查询智能体**纯只读消费**，与"解析负责写、查询只读"的既定边界一致。

## 6. 片段同步（一致性命门）

> 需求明确：标签后期会更新，须能**及时同步**。这是向量库长期正确性的命门。

| 变更源 | 同步要求 |
|---|---|
| 标签更新（如 `mod_service_ai` 由 0 改 1） | Milvus 对应片段的 metadata 及时更新，无需重算向量 |
| 原文更新（重新核对/换扫描件） | 对应片段的向量 + metadata 重建 |
| 四模块独立存储的价值 | 按**模块粒度增量重建**，不必整份合同重跑 embedding |

- **触发点**：随解析侧"人工核对入正式库"或"标签修订"动作联动更新向量库（具体机制在实现阶段设计：事件/批量重建/版本号比对，属实现细节）。
- **一致性判据**：查询命中的片段 metadata 必须与正式库当前值一致，不得用过期标签过滤。

## 7. 信任度与输出（防幻觉）

沿用查询模块 §5 的 >90% 准确率 / 不幻觉纪律，映射到 RAG：

- **出处引用（硬性）**：RAG 答案必须标注命中片段的**合同号 + 来源字段 + 原文引用**，等价于 SQL 的"查看 SQL 折叠框"透明度。
- **低相似度不编造**：精排最高分低于阈值时，如实回答"未找到足够相关的原文"，不生成臆测答案。
- **一致性**：RAG 引用的原文必须来自命中片段本身，不得改写原文含义。

## 8. 与结构化查询模块的关系（继承既定纪律）

本方案是查询模块的扩展，继承其已定决策（见该模块 CONTEXT.md 与 ADR-0001/0002）：

- Text-to-SQL + 三道只读防线；自纠错重试上限 2 次、空结果只提示不放宽。
- 金额分口径求和、`amount IS NOT NULL`、税率 TEXT 不可算。
- 语义时间由 Agent 推理（schema 只给列语义）。
- **禁止同一轮同时调两个工具**：语义路由路径下 `sql_query` 依赖 `vector_search` 的输出，串行。

## 9. 与整体架构的关系（更新）

```
【合同解析模块】(独立 Python)
   PDF → MinerU → MD(带格式分段片段) → LLM分组抽字段 → 模块切分+关键词检测
        → 草稿区 →(人工核对)→ 正式库 contracts(SQL 字段 + 原文)
        └─(新增)→ 持久化完整分段片段 + qwen3-embedding → 写 Milvus
                                                    │
                              ┌─────────────────────┼──────────────────┐
                              ▼ 共享 PostgreSQL      ▼ 共享 Milvus
【经小管查询 Agent】(CoreMind 单 Agent)
   自然语言提问 → 自主编排:
     ├ sql_query (只读 Text-to-SQL)                    → Markdown 表格
     ├ vector_search (Milvus 召回50 → reranker 精排8)  → RAG 原文答案(带出处)
     └ 联动: vector_search 返 contract_ids → sql_query  → 统计表格
```

- 解析与查询仍**解耦**，耦合点从"共享 PG"扩展为"共享 PG + 共享 Milvus"。
- 片段一入库即建向量，查询侧全程只读。

## 10. 验收标准（语义检索部分）

- **RAG 准确率（>90%）**：答案依据的原文片段与提问相关；引用原文不篡改含义。
- **出处完整性**：每条 RAG 答案都带合同号+字段+原文引用，可人工回溯。
- **不幻觉**：低相似度场景明确说"未找到"，抽检 0 编造。
- **路由正确性**：纯统计问题不触发向量检索；语义问题正确走召回+精排；联动路径串行不并发。
- **同步正确性**：标签/原文更新后，检索用的 metadata 与正式库一致（无过期标签命中）。
- **评测方式**：首版 gate 以 trajectory（路由/串行正确）+ 出处完整性 + 不幻觉抽检为准；语义相关性的数值化评测（如人工标注相关性）随测试库后续里程碑建立。

## 11. 已确认决策（本轮 grilling 逐条确认）

- ✅ 检索形态：RAG 原文问答 + 语义路由到统计**并存**，由 Agent 自主判断（Q1-C）
- ✅ 检索范围：单合同锁定追问 + 全库语义检索**并存**（Q2-C）
- ✅ 向量化范围：**合同全文**（MinerU 完整分段片段，非仅 7 类字段）（Q3→Q9→Q10）
- ✅ 切分：结构感知（按字段/章节切父块，超长按条款切，重叠防切断），带 4 元 metadata（Q4）
- ✅ 向量库：**Milvus**（独立，非 pgvector）（Q5）
- ✅ embedding：**qwen3-embedding-4B**（Q5）
- ✅ 精排：**qwen3-reranker-4B 两阶段**，召回50→精排8（Q8）
- ✅ 会话状态：靠 session 历史 + prompt 推断当前合同，不加显式状态工具（首版）（Q6-B）
- ✅ 出处引用：RAG 答案硬性标注合同号+字段+原文；低相似度不编造（Q7）
- ✅ 片段归属：**解析侧持久化完整分段 + 解析侧建向量**（Q10-A，已授权跨解析模块）
- ✅ 四模块**单独存储**，支持按模块粒度增量同步（Q10）
- ✅ 片段同步：标签/原文更新须及时同步向量库（§6）
