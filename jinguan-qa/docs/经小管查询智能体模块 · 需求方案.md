经小管查询智能体模块 · 需求方案

版本: v1.0 (草案) · 生成日期: 2026-08-11 归属: 经小管合同管理智能体 · 本方案针对 查询问答与综合检索。

1. 模块目标

基于 CoreMind 架构，构建一个能够理解用户自然语言、自动调度 SQL 工具、并汇总生成报表的“经管专家”。 一句话职责：自然语言提问 → 意图拆解 →
SQL 生成与执行 → 数据汇总/对比分析 → Markdown 表格输出。

2. 职责边界 (已确认)

本模块端到端负责：提问理解 + 检索调度 + 答案生成。

  - ✅ 输入：用户自然语言提问（如：前两季度含 AI 标签的合同总额）。
  - ✅ 数据源：正式库 contracts（包含结构化字段 + 4 模块原文）。
  - ✅ 输出：Markdown 格式的文字回答 + 统计表格。
  - ❌ 不负责：解析入库（由解析模块负责）。

3. 智能体架构设计 (基于 CoreMind)

3.1 核心组件设计

1.  Harness 层 (工具封装)：
      - sql_query_tool：封装 PostgreSQL 连接，将 LLM 生成的 SQL 语句在正式库中执行。
      - schema_service：动态向 LLM 提供 contracts 表的最新字段说明、枚举值口径（如：金额属性的含义）。
2.  Memory 层 (上下文记忆)：
      - Session Memory：记录对话上下文，支持多轮追问（如：“那第三季度的呢？”）。
      - Domain Knowledge：存储“AI标签”和“通信标签”的层级结构定义，辅助 Agent 理解用户模糊指令。
3.  Planning 层 (任务拆解)：
      - 采用 ReAct (Reasoning + Acting) 循环。
      - 复杂查询拆解：针对跨维度提问（如：对比 AI 合同和非 AI 合同的平均金额），智能体需将其拆分为多个 SQL 查询并进行二次逻辑计算。

4. 关键检索逻辑 (针对合同特性)

4.1 确定性统计逻辑 (Text-to-SQL)

  - 时间转换：Agent 必须具备将语义时间（如“前两季度”、“去年下半年”）转化为 SQL 时间过滤条件（sign_date BETWEEN
    ...）的能力。
  - 标签检索：利用解析模块预存的 tag_ai (0/1) 字段进行快速过滤。
  - 金额口径：Agent 在生成 SQL 时必须默认遵循：
      - WHERE amount IS NOT NULL（剔除框架协议等无金额合同）。
      - 明确“金额属性”口径（上限/固定/预估），并在输出结果时予以标注。

4.2 模块化细粒度查询 (4 模块检索)

  - 利用解析模块录入的 mod_service_ai / mod_tech_ai / mod_role_ai / mod_staff_ai 字段。
  - 场景示例：用户问“有哪些合同在‘服务内容’里提到了 AI，但在‘技术要求’里没提？”
  - SQL 实现：SELECT ... WHERE mod_service_ai=1 AND mod_tech_ai=0。

5. 验收标准 (准确率与稳定性)

  - KPI 准确率 (> 90%)：
      - SQL 准确率：生成的 SQL 语法正确，且符合业务逻辑口径。
      - 回答一致性：表格数据必须与 SQL 执行结果完全一致，不得产生幻觉。
  - Self-Correction (自纠错) 逻辑：
      - 若 SQL 执行报错，Agent 需利用 CoreMind 的 Loop 机制捕获 Error，重新阅读 Schema 并修改 SQL
        再次执行。
      - 若 SQL 返回结果为空，Agent 需尝试放宽条件（如：从精确匹配改为模糊匹配）并提示用户。

6. 开发与测试计划 (与解析模块同步)

6.1 测试集制作 (Test Suite)

  - 定量题库：预设 50 条统计类问题（含跨年份、跨标签、跨模块维度）。
  - 定性题库：预设 20 条条款解释类问题。
  - 跑分机制：对比 Agent 输出的表格数据与人工核对后的正式库快照数据。

6.2 20 号初版目标

1.  完成 contracts 表的 Schema 挂载。
2.  实现基础的 Text-to-SQL 工具。
3.  支持基于“时间 + 标签 + 4 模块”组合维度的自然语言统计。
4.  只读原则：查询 Agent 工具集对 contracts 表仅拥有 SELECT 权限，严禁写操作，确保正式数据安全。
5.  透明度：在 Agent 的输出界面，建议预留一个“查看 SQL 语句”的折叠框，供专业用户校验，增加信任度，防止误解引发投诉。
6.  无结果提示：严禁 AI 在查不到数据时编造。必须明确提示“当前正式库中未检索到满足条件的记录”。
