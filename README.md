# 经小管合同管理智能体

合同与订单台账、合同解析、AI 关键词识别、向量检索及综合检索系统。

## 当前架构

```
Vue 前端 (:5174) → Koa 网关 (:3002)
  ├─ 运营库：用户、角色、菜单、订单、关键词、重扫任务
  ├─ 查询库：已核对合同、模块命中、关键词命中、原文件关联
  ├─ 解析服务 (:8100)：PDF/附件解析、人工核对、向量化
  └─ 查询智能体 (:8101)：只读 SQL、RAG、会话记忆
查询库 → Milvus：仅已核对合同的正文片段
EPMS 同步：订单与附件增量同步
```

合同与订单为独立台账。合同—订单关联结构已预留，但无人工确认数据前，页面入口和混合业务统计保持停用。

## 已实现

- 合同上传、Markdown 解析、字段抽取、人工核对、正式入库及向量化。
- 合同台账的动态模块 AI 标记、关键词 AND 筛选、核对/查看/编辑、原文件下载和删除。
- 合同详情六页签：基本信息、金额及结算、商务条款、风控、关键词识别结果及明细、原文件预览。
- 关键词父词/子词管理；合同管理员和系统管理员可异步重扫合同和订单关键词，不重解析或重建向量。
- EPMS 订单台账、动态模块筛选和 AI 标记、人工覆盖编辑。
- 综合检索：受控只读 SQL、RAG、台账表格和 Excel 导出，保留会话历史。

## 关键规则

- 只有人工核对后的合同进入正式库和 Milvus；草稿绝不建向量。
- `tag_ai=1` 表示任一模块命中；模块列只显示 `AI` 或 `—`。
- 关键词明细：子词为“关键词”，父词为“所属大类”。
- 综合检索默认返回台账明细及合同金额汇总；用户明确要求时才按金额口径拆分。

## 启动

各服务使用自己的 `.env`，不得提交密钥。

```bash
cd apps/parse-service && uvicorn jinguan_parse.api:app --host 0.0.0.0 --port 8100
cd apps/query-agent && npm run start
cd apps/gateway && npm run start
cd apps/web && npm run dev -- --host 0.0.0.0 --port 5174
```

详细边界见 [docs/current-architecture.md](docs/current-architecture.md)。历史原型和旧需求方案不作为当前实现依据。
