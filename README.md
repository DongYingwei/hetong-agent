# 经小管合同管理智能体

合同与订单台账管理、合同附件解析、AI 关键词识别、合同正文向量检索和综合检索系统。

## 当前状态（2026-08-20）

- 合同正式台账：以 `demo/合同台账-V2.xlsx` 为基线，已确认 **59** 份，均已人工核对；原始附件可一合同对应多份 PDF。
- 订单正式台账：`contract_assistant.sys_order` 共 **9,815** 条；当前全文 AI 初筛 **338** 条。订单附件、Markdown、关键词初筛结果在服务器数据盘保存。
- 合同链路可用：上传单附件、同合同多附件或合同 ZIP 包 → 草稿解析 → 人工填写真实合同号并核对 → 正式入库 → 仅前 50 页切片、向量化。
- 合同与订单为两套独立台账。合同—订单关联表仅为后续人工确认关系预留；未提供确认数据前不作为日常查询或金额统计依据。

## 架构

```text
Vue 前端 (:5174) → Gateway (:3002)
  ├─ 运营库 contract_assistant：用户、角色、菜单、关键词、订单、会话
  ├─ 合同库 contracts：合同、附件、草稿、核对、模块/关键词命中、切片
  ├─ Parse Service (:8100)：合同上传、解析、核对、向量化
  └─ Query Agent (:8101)：只读 SQL、合同正文 RAG、受控业绩统计
contracts → Milvus：仅已确认合同、且仅已解析前 50 页的正文片段
EPMS timer：订单附件/Markdown/全文关键词初筛（不自动重导订单主表）
```

详细运行边界见 [当前架构](docs/current-architecture.md)，部署见
[服务器迁移与发布手册](docs/deployment-migration-runbook.md)，当前进度见
[handoff.md](handoff.md)。

## 已实现能力

- 合同台账、订单台账的查询、筛选、详情、编辑、导出和权限控制。
- 合同详情六页签：基本信息、金额及结算、商务条款、风控、关键词解析、原文件预览。
- AI 关键词父词/子词管理；四个固定业务模块：项目名称、服务内容、技术要求、人员需求。
- 合同和订单关键词重扫：只更新命中、模块标记和 `tag_ai`，不重新解析附件或重建合同向量。
- 综合检索：合同/订单只读结构化查询、合同正文 RAG、会话记忆、超长输入和无关问题引导、台账明细与 Excel 导出。
- 操作日志记录后台与用户侧关键操作。

## 关键业务规则

- 合同级 `tag_ai=1` 表示全文命中关键词；四模块各自只展示 `AI` 或 `—`。
- 关键词明细中“关键词”为命中的子词，“所属大类”为关键词管理的父词。
- 合同未通过人工核对不得进入正式库或 Milvus；新上传合同保持待核对。
- 原始 PDF 一直完整保留、预览和下载；为避免超时，解析、关键词扫描和向量化只处理前 50 页。
- 综合检索的合同、订单金额默认在各自台账内统计；只有已有人工确认关联且明确提出混合业绩口径时，才允许合并计算。

## 本地启动

所有服务使用各自 `.env`，不得提交密码、JWT 或模型密钥。

```bash
cd apps/parse-service && uvicorn jinguan_parse.api:app --host 0.0.0.0 --port 8100
cd apps/query-agent && npm run start
cd apps/gateway && npm run start
cd apps/web && npm run dev -- --host 0.0.0.0 --port 5174
```

生产发布不要直接复制以上命令，请使用
[服务器迁移与发布手册](docs/deployment-migration-runbook.md) 的 `systemd + release` 流程。
